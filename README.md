# 多 Jenkins 发布管道工具

一个 Windows 桌面小工具，把「按环境顺序逐个发布同一个服务」这件重复劳动自动化：

1. 在列表里勾选要发布的服务（常用的可以标成 ★，下次直接筛出来）；
2. 点「加入队列（N）」，所有服务**并行**开始，各自沿环境链逐级推进；
3. 某个服务在某级环境构建 **成功** 后，自动在下一级触发 **同名 Job**；
4. **每个任务跑完各自弹一次系统通知**，告诉你这个服务的结果，文案可以自己改。

环境级数是**任意**的，想配几级配几级（如 `dev → sit → uat → prod`），数组顺序就是执行顺序。

技术栈：Tauri 2 + React 19 + TypeScript + Vite 8，后端 Rust；只调 Jenkins 标准 REST API，
实测对象是 **2.528.x**。代码里没有按 Jenkins 版本分支的逻辑，但其它版本未经实测。

---

## 快速开始

```bash
pnpm install          # 装前端依赖（仓库用 pnpm，有 pnpm-lock.yaml）
pnpm tauri dev        # 开发模式：自动拉起 Vite(1420) 并打开窗口
pnpm tauri build      # 打包安装包
```

要求：Rust 工具链（`cargo`）、Node.js、pnpm。Windows 上还需要 WebView2 ——
打包配置用了 `downloadBootstrapper`，安装时自动下载；开发机一般已随 Edge 装好。
`pnpm build` 会先跑 `tsc` 做类型检查，再过 Vite 打包。

> 单实例互斥见「托盘、窗口与单实例」：`pnpm tauri dev` 起的那份和你已安装的副本
> 算同一个程序，后启动的会被直接拦掉。

## 界面长什么样

单窗口、两个页签，没有路由，切换只是一个 `useState`：

| 页签 | 内容 |
| --- | --- |
| **发布** | 左侧「选择服务」+「加入队列」按钮；右侧「发布队列」卡片板 + 「日志」面板 |
| **设置** | 「流水线环境」「完成通知文案」「使用说明」三个面板 |

- 标题栏副标题显示当前环境链（如 `dev → sit → uat → prod`），还没配时显示「还没配置流水线环境」。
- 缺配置时，发布页顶部会列出具体缺什么（地址 / 用户名 / API Token）并给一个「去设置」快捷按钮；
  设置页签上有个琥珀色圆点提示「还有配置未完成」。
- 窗口默认 1220×820，最小 900×620；宽度收到 900px（也就是最小宽度）时，两栏布局自动塌成一栏。
  深色配色写死在 `App.css`，没有主题开关，也没有多语言（文案全是硬编码中文）。
- 队列全部跑完且卡片非空时，底部会浮出一条汇总栏（`队列已全部完成` / `队列已完成，N 个任务失败`）。

## 首次配置

进 **设置 → 流水线环境**，按发布顺序逐个添加环境。「＋ 添加环境」新建的环境默认名是
`stage-1`、`stage-2`…（自动避开重名），默认 5 秒轮询、90 分钟超时、两个勾选项都关。
每条环境**默认折叠**，点标题栏展开编辑。

| 字段（界面上的原文） | 说明 |
| --- | --- |
| 环境名（同时作为凭据名） | 如 `dev` / `sit` / `prod`。它既是显示名也是标识，**还是凭据的键**，见下节 |
| Jenkins 地址 | 例如 `http://jenkins-dev.corp.local:8080`，不要带 `/job/...`，末尾斜杠会被去掉 |
| 用户名 | Jenkins 登录账号 |
| API Token | 在 Jenkins 的 **个人设置 → Security → API Token** 里生成。输入框是密码型，`已保存，留空则不修改` |
| 轮询间隔（秒） | 查队列项和构建状态的频率，默认 **5**；填 0 或非法值会回落到 5 |
| 单次构建超时（分钟） | 默认 **90**；填 0 或非法值会回落到 90。注意它是**两段各自的**超时，见「执行逻辑」 |
| 忽略 TLS 证书校验（仅在内网使用自签名证书时打开） | 打开后同时关闭证书校验和主机名校验 |
| 本级失败后中止整条流水线（不勾选时，后面环境会继续发布） | 默认不勾选 |
| 命中此阶段即算本级成功（忽略后续 stage） | 留空表示按整条构建结果判定，见「执行逻辑」一节 |

- **↑ ↓** 调整顺序（数组顺序就是执行顺序），**✕** 删除该环境（有原生 confirm）。
- 点 **保存** 落盘；点 **测试连接** 会显示一行结果，成功时把 Jenkins 版本一起写进那句话里，
  顺便核对版本；**清除 Token** 只在已存有 Token 时出现。
- Token 是在保存环境**之前**先写入凭据管理器的（输入框非空即写）。
- 折叠标题上会显示 `已存 Token` / `未存 Token`，开了中止则多一个 `失败即中止` 标签。

### Token 存在哪里

**API Token 不会写进配置文件**，而是交给 Windows 凭据管理器（「控制面板 → 凭据管理器 →
Windows 凭据」）。一个环境一条，`用户名` 就是环境名，条目名由 keyring 按「`用户名.服务名`」
拼出，形如 `dev.multiple-jenkins-build-pipeline-tool`。

界面上留空输入框不等于清空 Token —— 只有点 **清除 Token** 或提交空白值才会删。

**给环境改名时，工具会自动把已保存的 Token 挪到新名字下**，正常改名不会丢 Token。
但如果新名字下本来就存过 Token，则保留新名字那一份、不动旧条目（不覆盖）。

### 配置文件

```
%APPDATA%\com.muedsa.multiple-jenkins-build-pipeline-tool\config.json
```

- 内容是美化过的 JSON，写入走「先写 `config.json.tmp` 再 rename」，避免半截文件。
- **文件缺失或解析不出来时静默回退到默认配置**（`dev` + `test` 两个空环境、空服务清单、默认文案），
  不报错也不备份 —— 那个坏文件会一直留在磁盘上，直到下一次保存覆盖它。
- 老配置会自动迁移：v1 的顶层 `dev` / `test` 两段会被读成两级环境，环境名固定回落为
  `dev` / `test`，**故意保持和凭据键一致**，免得升级后 Token 突然“找不到”。
  迁移只看数据形状，文件里的 `version` 字段读时被忽略，写出时统一置为当前版本（`2`）。
- 保存前会做规范化：去掉空名字和重名环境（保留第一个）、服务名去空格去重。

## 添加服务

回到 **发布** 页，服务清单是**本机配置**，不会跟着仓库走。两种方式：

### 从 Jenkins 搜索添加（推荐）

点「**☁ 从 Jenkins 搜索**」，工具调**流水线里第一个环境**（服务清单按「各环境同名 Job」
约定维护，列第一个环境就够）拉取全部可构建 Job，在弹窗里勾选、批量添加 ——
不用手输，也就不会把 Job 名写错。

- 列表**只在打开弹窗时拉一次**，之后搜索全是本地过滤（按完整名或末级名，不区分大小写），
  不会每敲一个字就打一次 Jenkins。
- **一次最多显示 200 条**，已添加的排到后面；超出的会提示「输入关键字可继续筛选」。
- 已经在清单里的标 `已添加` 并置灰；带文件夹层级的用灰色小字补出完整路径（`team-a/svc-1`）。
- **文件夹、多分支流水线、View 这类容器不会出现在列表里** —— 它们本身不能直接触发构建，
  工具会递归进容器只收集可构建的 Job（FreeStyle / Pipeline / Maven / Matrix 等）。
- 确认后走的是批量添加接口（已存在的自动跳过），并且**新加的服务会被自动勾上**。

### 手动输入

点「**＋ 手动输入**」（再点一次取消），文本框里可以一次粘一批：
换行、半/全角逗号、分号、空格都会被当成分隔符。适合 Jenkins 一时连不上、
或想先按约定把服务名列好的场景。

### 通用说明

- **服务名就是 Jenkins Job 名**，约定各级环境上是同名 Job，只是服务器不同。
  支持文件夹型 Job，用 `/` 分层即可，例如 `team-a/order-service`。
- 如果 Job 需要参数，点行尾 **✎** 打开编辑弹窗加「参数名 / 参数值」。带了参数的服务在列表里
  标一个 `参数 n`，触发时会带上表单值。
- 点 **★** 标为常用，之后勾「只看常用」快速筛出来；**✕** 删除（原生 confirm）。
- 勾选支持搜索框过滤、`全选当前`（只选筛出来的）和 `清空`；面板标题实时显示 `已选 n / m`。
- 每次入队都会把这次勾选记进配置（`lastSelection`），下次打开自动回填；如果记下的服务后来被删了，
  就退回勾选全部「常用」项。

## 发布队列与执行逻辑

一个「服务 × 一条流水线」是一个**独立任务**，任务 id 形如 `task-1`（界面上不显示）：

- **入队即开跑，全部并行**：每个服务一个协程，入队瞬间全部启动，互不等待。
- **任务内部逐级串行**：沿 `dev → sit → uat → prod` 依次推进，上一级成功才进下一级。
- **卡片状态**：`等待` / `排队中` / `执行中` / `成功` / `失败` / `已跳过` / `已取消`
  （`执行中` 带小转圈）。每一级单独一行，有自己的状态、构建号 `#42`、耗时和
  `日志 ↗`（用系统浏览器打开该次构建页面）。
- **某一级失败的默认行为**：只把该级标为失败，**后面的环境继续发布**。
- **勾了「本级失败后中止整条流水线」**：该级失败后，它后面所有级都标 `已跳过`，
  理由写「上一级 X 未成功且设为失败即中止，故跳过本级」。判定用的是**刚跑完那一级**的开关。
- **只有 `SUCCESS` 算成功**：`UNSTABLE`（有测试失败）按失败处理，免得带着问题往下走；
  `ABORTED` 和未知结果也都不算成功。
- **看得到 Job 内部跑到哪一步**：等待期间每轮轮询都会顺带读一次 Jenkins Pipeline 的阶段列表，
  环境行下面列出各阶段（`✓ Checkout`、`● Deploy`、`○ Verify` 这样），阶段一挪动就在日志里记一行。
  阶段名旁边是它自己的耗时。
- **命中即放行（环境上填了 stage 名时）**：该阶段一旦成功，本级直接算 `成功` 并开始下一个环境的
  构建，**不等它后面的阶段跑完** —— 典型用法是 Jenkinsfile 里 `Deploy` 之后还有推送通知、
  清理workspace 之类不关心成败的收尾阶段。此时：
  - 卡片上会标「按阶段「Deploy」提前放行」，耗时记的是**我们实际等了的时长**，不是 Jenkins 的构建时长；
  - 阶段名匹配不区分大小写、两侧空格会被忽略，只有状态为 `SUCCESS` 才算命中；
  - **Jenkins 上那条构建不会被中断**，它会自己跑完，工具只是不再看它；
  - 填了名字但一直没出现同名阶段（拼错、或那是 FreeStyle Job）时，本级退回按整条构建结果判定，
    并在日志里提醒一次，不会因此卡死或误判失败。
- **单个取消**：卡片右上角 `⊘` 只取消那一个任务，其他任务照常跑，队列不清空。
  **没有「一键取消全部」**。
- **重新入队**：同一个服务可以反复加入队列（每次都是新任务），方便重跑。
- **清理**：队列头部的「清理已结束」（只在有已结束任务时出现）把 `成功/失败/已跳过/已取消`
  移出列表，还在跑的不动。排序规则是执行中/排队 → 等待 → 已结束。
- **整批预检查**：入队前会先把所有环境的客户端建好，所以**任何一个环境没配好（缺地址、
  缺用户名、没存 Token）都会让整批拒绝入队**，并提示「请在「设置」中补全「X」环境信息」，
  而不是跑到那一级才失败。
- **配置在入队那一刻冻结**：环境链、参数、通知文案都拷进任务里，跑到一半改设置不影响已入队的任务。
- **日志**：右侧「日志」面板按 `queue-event` 增量追加，显示时间和内容（事件里还带级别与所属
  任务 id，级别用于着色，任务 id 界面上不显示），可关「自动滚动」。
  日志和队列状态**都只在内存里**，不落盘、没有条数上限，重启程序即清空。

### 通知

**每个任务跑完各自弹一次**，文案里带服务名和它自己的结果，不会等整批结束才提醒。
三种结果各有一套标题+内容（`成功` / `失败` / `被取消`），默认值：

| 结果 | 默认标题 | 默认内容 |
| --- | --- | --- |
| 成功 | `✅ {{serviceName}} 发布完成` | `已在 {{stageChain}} 全部发布成功（耗时 {{duration}}）` |
| 失败 | `❌ {{serviceName}} 发布失败` | `卡在 {{failedStage}}：{{status}}（链路 {{stageChain}}，耗时 {{duration}}）` |
| 被取消 | `⊘ {{serviceName}} 已取消` | `任务被手动取消，停在 {{failedStage}}（耗时 {{duration}}）` |

- 「存在失败时使用另一套文案」这个开关**只管失败**那套；被取消的文案始终生效。
- 标题或内容被清空时，后端会兜底成 `发布全部完成` / `发布存在失败` / `任务已取消`
  加一句「成功 N 个，失败 M 个」，不会弹出空白通知。
- 已结束的任务卡片上有 `↻`，可以单独重发它的通知（通知内容会随任务留着）。
- 通知发送失败**不会**影响发布结果，也只是静默（不会弹错误框）。程序启动时会请求通知权限。

### 通知文案变量

设置页里可以用这些 `{{占位符}}`（渲染器支持 14 个）：

| 变量 | 含义 |
| --- | --- |
| `{{serviceName}}` | 本次通知对应的服务名（通知按服务发，这条最常用） |
| `{{reachedStage}}` | 实际推进到的最后一级环境 |
| `{{failedStage}}` | 出错或被取消的那一级环境 |
| `{{stageChain}}` | 环境链路，如 `dev → sit → prod` |
| `{{stageCount}}` | 环境个数 |
| `{{status}}` | 本任务结论：`成功` / `失败` / `已取消` |
| `{{duration}}` | 本任务耗时，例如 `3分12秒` |
| `{{finishedAt}}` | 完成时刻 |
| `{{serviceCount}}` | 单任务通知里恒为 `1` |
| `{{successCount}}` / `{{failedCount}}` | 单任务通知里为 `1 / 0`（成功）或 `0 / 1`（失败或取消） |
| `{{serviceList}}` / `{{successList}}` / `{{failedList}}` | 单任务通知里就是该服务名（或空串） |

- 设置页点变量标签会把占位符**追加到「成功内容」末尾**（不会插到标题或失败文案里），
  需要放到别处就手动粘。
- 预览是防抖 150ms 的实时预览，用的是写死的示例数据（3 个服务、2 成功 1 失败、
  `dev → sit → prod`、耗时 `6分12秒`），并且**总是同时渲染成功和失败两条**，好让你一眼比两边。
- 写错的变量名会**原样保留**（连 `{{}}` 一起显示），方便一眼看出拼错了，而不是被悄悄替换成空白。

### 托盘、窗口与单实例

程序常驻托盘，**点窗口右上角的关闭按钮只会最小化到托盘，不会退出** ——
发布可能还在跑，误点关闭不该把程序杀掉。

| 操作 | 效果 |
| --- | --- |
| 点窗口关闭按钮 | 隐藏到托盘，程序继续在后台跑（发布不受影响） |
| 左键单击托盘图标 | 把窗口重新显示到前台（只在左键抬起时触发，避免弹两次） |
| 右键单击托盘图标 | 弹出菜单：显示主窗口 / 退出程序 |
| 菜单里选「退出程序」 | 真正退出 |
| 程序已在跑时再次启动 | 新进程立刻退出，把已有窗口唤回前台 |

托盘图标悬停提示为「Jenkins 发布管道」。托盘建不起来不致命，只记一条日志继续跑。

**程序只允许一个实例**，由 `tauri-plugin-single-instance` 实现（桌面三平台，移动端不装）。
第二个进程把命令行参数和当前工作目录交给第一个进程后自行退出；第一个实例唤回主窗口
并在 stderr 日志里记下转发过来的参数。重复双击图标不会开出第二个程序，
也不会让同一批服务被发布两次。

互斥的键是 `tauri.conf.json` 里的 identifier（`com.muedsa.multiple-jenkins-build-pipeline-tool`），
**不是 exe 路径** —— `pnpm tauri dev` 起的那份和已安装的副本算同一个程序，后启动的照样会被拦掉。
开发时要两份同时跑，只能先退掉另一份。

## 它是怎么调 Jenkins 的

用的都是标准 REST 接口，认证一律 **HTTP Basic（用户名 + API Token）**，每次请求都带。
`{jobPath}` 是 Job 名按 `/` 拆开、每段前面加 `job/` 拼出来的，所以
`team-a/order-service` → `job/team-a/job/order-service`；非 `A-Za-z0-9-_.~` 的字节按大写
百分号转义，空格和中文名都能过。

| 用途 | 请求 |
| --- | --- |
| 探测连通性 / 版本 | `GET {base}/api/json?tree=mode,nodeDescription,version` |
| 列出可构建 Job | `GET {base}/api/json?tree=jobs[name,fullName,url,_class]`（递归进容器，结果按名字排序去重） |
| 取 CSRF crumb | `GET {base}/crumbIssuer/api/json` |
| 触发构建 | `POST {base}/{jobPath}/buildWithParameters` 或 `POST {base}/{jobPath}/build` |
| 队列项查构建号 | `GET {queueUrl}/api/json?tree=executable[number,url],why,cancelled` |
| 查构建状态 | `GET {base}/{jobPath}/{n}/api/json?tree=number,building,result,duration,url,displayName` |
| 查 Pipeline 阶段 | `GET {base}/{jobPath}/{n}/wfapi/describe`（**非原生接口**，来自 Pipeline Stage View 插件） |

实现上几个值得知道的点：

- 用 token 而不是密码，所以在 Jenkins 2.528.x 收紧密码认证之后依然可用。
- **crumb 不缓存**：每次 POST 前现取一次，取到的字段名按 Jenkins 返回的 `crumbRequestField`
  原样当请求头。目标实例没开 CSRF 保护时（取不到 crumb）就直接不带，照样触发。
  同时开了 cookie 支持，保证 crumb 和会话能对上。
- 端点选择：服务带了参数就只走 `buildWithParameters`；**没带参数时先试 `build`**，
  如果 Job 其实定义了参数（Jenkins 回 `400 Nothing is submitted`），自动改走
  `buildWithParameters` 用 Job 自己的默认值。这是全流程里唯一一次「重试」，
  认证失败、403、404 之类不会换端点重打。
- 触发成功以 2xx 判定（新版 201，旧版可能 200），构建号要从队列项里读，
  所以「排队中」和「执行中」是两个阶段。
- 成功时 Jenkins 的 `Location` 头常常是**相对路径**（`/queue/item/12/`）。客户端会补成绝对地址，
  并去掉所有末尾斜杠 —— 否则拼查询串会得到 `/queue/item/12/?tree=` 这种取不到数据的地址。
  万一没有 `Location`，退回队列首页 `{base}/queue`。
- 队列项里 `cancelled` 为真（构建在排队时就被取消）会直接判失败并给出原因。
- **阶段接口是尽力而为的**：每轮轮询随构建状态一起请求 `wfapi/describe`；返回 404（没装插件）或
  响应读不懂时只试一次就不再打，本级退回按整条构建结果判定，不影响发布流程本身。
- 超时是**两段独立**的：等排队分配构建号最多 `timeout` 分钟，等构建结束又最多 `timeout` 分钟，
  所以一级最长可能占 `2 × 单次构建超时`。轮询超时会把 Jenkins 给的排队原因（`why`）带出来。
- 单次 HTTP 请求本身有 30 秒的客户端超时；轮询期间一次网络抖动就会把该级判失败（不重试）。
- TLS 走系统自带的 Schannel（`native-tls`），不引入 rustls/`aws-lc-sys`，
  因此在 MSVC 环境里不需要现编 C 代码。勾了忽略校验时，证书校验和主机名校验一起关。
- 错误会翻成人话，前缀是环境名：401「认证失败：请检查用户名和 API Token」、403「权限不足，
  或 CSRF crumb 校验失败」、404「找不到 Job「x」」、其它「Jenkins 返回 HTTP nnn + 前 200 字正文」，
  另有连接失败与响应解析失败两类。

前后端约定：

- 类型字段一律 camelCase，和后端 `#[serde(rename_all = "camelCase")]` 对齐；
  命令参数也是 camelCase（`taskId`、`originalName`、`pollIntervalSecs`）。
- 队列是**推送驱动**的：后端每次状态变化 `emit("queue-event", { seq, logs, queue })`，
  快照整体重发、日志只发增量，前端按 `seq` 丢弃乱序事件；
  窗口重新获得焦点时再补一次 `queue_status`，防止最小化期间漏事件。**没有定时器轮询。**
- 任务级和每一级共用同一套状态枚举 `pending|queued|running|success|failed|skipped|cancelled`。
- 时间戳是后端就格式化好的字符串，前端原样显示；耗时用 `humanizeDuration`，
  前后端两份实现保持一致（`1小时2分5秒` / `3分12秒` / `45秒`）。
- 打包配置里 `csp: null`（不启用 CSP），发布前若要收紧需自行加。

跑测试：

```bash
cd src-tauri
cargo test
```

集成测试自己起一个 `127.0.0.1:0` 的假 Jenkins，覆盖触发、排队、轮询、成功 / 失败 / 不稳定、
401、404、队列超时、`Location` 相对路径补全、文件夹递归、参数化 Job 的 400 回退、
以及地址/用户名/token 缺失的本地校验。

其中需要往**真实**系统凭据管理器写测试 token 的用例**默认跳过**（不想在你的凭据里留东西）。
要连这些一起跑，**必须单线程**，且需要显式打开开关：

```powershell
# PowerShell
$env:JENKINS_TOOL_KEYRING_TESTS = "1"; cargo test -- --test-threads=1
```

> 为什么必须单线程：Windows 凭据管理器的读写不是线程安全的，多个测试并发读写时
> 会偶发丢写（刚存进去马上读却读不到）。这是环境限制，不是被测代码的问题。
> 多线程下这些用例会自动跳过，不会误报失败。

> **还有个坑要留意**：用例里判断「是不是单线程」用的是 `available_parallelism()`，读的是进程
> 可用的 **CPU 核数**，不是测试线程数。所以在多核机器上，即使命令行加了 `--test-threads=1`，
> 这批用例依然会静默跳过 —— 输出里显示 `ok`，其实一行断言都没执行。
> 真要跑它们，得把测试进程限制到单核（例如用进程亲和性绑核后再跑）。

测试用的条目名一律以 `inttest-` 开头，跑完自行清理。

本地跑法：`pnpm tauri dev`（Vite 固定 1420，`strictPort`，HMR 端口 1421 仅在设置了
`TAURI_DEV_HOST` 时启用；Vite 会忽略 `src-tauri/` 的文件变化）。

### 应用图标

图标源文件在 `tools/icons/`（Snapshot DSL + 各尺寸 PNG），设计说明见该目录下的 README。

`src-tauri/icons/` 里**每个尺寸都用手调的原图**，而不是从 512 主图自动缩放 ——
小尺寸下等比缩放会把箭杆缩进箭翼里、箭头糊成一团，所以 16 / 24 / 32 / 48px 是各自独立设计的。
组装方式：

| ico 档位 | 来源 |
| --- | --- |
| 16 / 24 / 32 / 48 / 64 | `tools/icons/release-pipeline-<尺寸>.png` 原图 |
| 256 | 512 主图 LANCZOS 缩一半（Windows 用 PNG 压缩存这一档） |

`icon.png` 用 512 主图，`32x32.png` / `128x128.png` 用手调原图，
`128x128@2x.png` 与 Windows Store 系列由 512 主图缩放。

改了图标后重新生成：

```bash
# 1) 重新渲染各尺寸 PNG（需要 Snapshot 服务）
powershell -File tools/icons/build-all.ps1
# 2) 按上表重新组装 src-tauri/icons（含多尺寸 icon.ico）
```

图标经 `.rc` 编译进 exe，改完必须重新构建才会生效。Windows 还会缓存 exe 图标，
看不到变化时把 exe 挪个目录或重启资源管理器即可。
托盘图标复用应用主图标（`default_window_icon`），左键唤窗、右键弹菜单。

## 已知限制

- **只看 Jenkins 的构建结果，不解析构建日志**，也不抓控制台输出。
- **队列和日志都是内存态**：重启程序后列表清空，正在跑的任务也随之丢失（程序退出并不会
  中断 Jenkins 上已经开始的构建，它仍在服务器上跑）。服务清单、环境配置存在本机配置文件里，
  不跟着仓库走。
- **`⊘` 取消只让本任务停止推进后续环境，不会调 Jenkins 的 `stop`/`kill` 接口** ——
  已经触发的构建会在 Jenkins 上继续跑完。取消标志只在**每一级开始之前**检查，
  排队或构建过程中点取消，要等这一级自己结束（成功、失败或超时）才生效。
- **没有「取消整个队列」「暂停」「失败自动重试」**，只能逐个任务处理。
- 阶段进度和「命中即放行」依赖 Jenkins 的 **Pipeline Stage View** 插件；没装插件、或 Job 是
  FreeStyle 这种没有阶段概念的 Job，就只剩环境级进度 —— 填了 stage 名也永远命中不了，
  本级会退回按整条构建结果判定。
- 一级可能占用两段各自的超时（等排队 + 等构建），最坏是设定值的两倍。
- 轮询期间的一次网络错误会直接把该级判失败，不做重试。
- 通知权限被拒或发送失败都是静默的，不会提示，也不会影响发布结论。
- 通知变量渲染器实际支持 14 个占位符，但设置页的变量标签只列出 11 个
  （`serviceName` / `reachedStage` / `failedStage` 没有标签，手写可用）。
- 两处**界面文案已过期**（不影响功能）：服务清单为空时提示的「＋ 添加服务」按钮并不存在
  （真实按钮是「＋ 手动输入」）；设置页「使用说明」最后一条写的「开始发布」，实际按钮叫
  「加入队列」。
